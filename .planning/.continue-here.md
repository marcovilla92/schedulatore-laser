### 2. PDF PARSER ALWAYS RETURNS DIVISIONE CUCINE (CRITICAL BUG)
**Problem**: All PDFs being parsed as DIVISIONE_CUCINE format, regardless of actual format.

**Symptom**: Tested with real PDFs:
- `OAFA202600125.pdf` → returns DIVISIONE_CUCINE (wrong)
- `FOR-ORDINE_0000173_00(50359).pdf` → returns DIVISIONE_CUCINE (wrong)

**Root cause**: Either:
- Backend `extract_pdf_data` endpoint not calling pdf_parser dispatcher correctly
- OR pdf_parser.py dispatcher broken and defaulting to divisione_cucine
- Need to check: `/api/extract-pdf-data` in app.py line ~400

**Files to debug**:
- `app/backend/pdf_parser.py` — check dispatcher logic
- `app/backend/app.py` — check extract_pdf_data route
- Test with simple curl: `curl -F "file=@test.pdf" http://localhost:5000/api/extract-pdf-data`
