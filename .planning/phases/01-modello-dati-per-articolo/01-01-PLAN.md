  <action>
Add a new `Article` SQLAlchemy model class to models.py with the following schema:

```python
class Article(Base):
    __tablename__ = 'articles'
    id = Column(String, primary_key=True)          # UUID string
    order_id = Column(String, ForeignKey('orders.id'), nullable=False)
    name = Column(String, nullable=False, default='')
    code = Column(String, default='')
    qty = Column(Integer, default=0)
    required_phases = Column(JSON, default=lambda: ['LASER', 'PIEGA', 'SALDATURA', 'PULIZIA', 'SPEDIZIONE'])
    attributes = Column(JSON, default=dict)         # Catch-all for format-specific fields (price, material, dimensions, etc.)
    order = relationship('Order', back_populates='article_records')
    processing_steps = relationship('ProcessingStep', back_populates='article', cascade='all, delete-orphan')
```

Design decisions (Claude's discretion per CONTEXT.md):
- `required_phases` as JSON list column (not normalized table) — matches existing SQLAlchemy JSON patterns in this codebase
- `attributes` JSON column for any extra fields from different PDF formats (price, material, weight, etc.) — keeps schema flexible
- Default all 5 phases per user decision: ['LASER', 'PIEGA', 'SALDATURA', 'PULIZIA', 'SPEDIZIONE']
- Use `default=lambda:` for mutable defaults (existing pattern, see STATE.md decision about flag_modified)

Update the `Order` model:
- Add relationship: `article_records = relationship('Article', back_populates='order', cascade='all, delete-orphan')`
- Keep the existing `articles` JSON column for backward compatibility (old data still readable)
- Add a comment: `# LEGACY: JSON articles kept for backward compatibility with pre-v1.1 data`

Update the `ProcessingStep` model:
- Add column: `article_id = Column(String, ForeignKey('articles.id'), nullable=True)` — nullable for backward compat with existing steps that have no article
- Add relationship: `article = relationship('Article', back_populates='processing_steps')`

Export `Article` from the module — add it to any imports list if applicable.

IMPORTANT: Do NOT remove or rename any existing columns or relationships. The old `articles` JSON column on Order stays. The old `completed_articles` JSON on ProcessingStep stays. This ensures pre-v1.1 data keeps working.

<task type="auto">
  <name>Task 2: Create migration utility for existing orders</name>
  <files>app/backend/migrate_articles.py</files>
  <action>
Create a new file `app/backend/migrate_articles.py` with a migration utility that:

1. **`migrate_existing_orders()`** function:
   - Opens a database session
   - Queries all Order records that have `articles` JSON data but no corresponding Article records in the articles table
   - For each order with JSON articles:
     - For each article dict in `order.articles`:
       - Create an `Article` record with:
         - `id`: new UUID
         - `order_id`: the order's id
         - `name`: article.get('name', '')
         - `code`: article.get('code', '')
         - `qty`: article.get('qty', 0)
         - `required_phases`: article.get('required_phases', ['LASER', 'PIEGA', 'SALDATURA', 'PULIZIA', 'SPEDIZIONE'])
         - `attributes`: dict with all other keys from the article dict (exclude name, code, qty, required_phases)
     - Commit per-order (not per-article) for transactional safety
   - Print progress: "[MIGRAZIONE] Ordine {order.id} ({order.cliente}): {N} articoli migrati"
   - Return dict with `{"migrated_orders": N, "migrated_articles": M, "errors": [...]}`

2. **`ensure_articles_table()`** function:
   - Calls `Base.metadata.create_all(bind=engine)` to ensure the articles table exists
   - This is idempotent — safe to call multiple times

3. **`run_migration()`** function:
   - Calls `ensure_articles_table()` then `migrate_existing_orders()`
   - Prints summary
   - This is the main entry point

4. Add `if __name__ == '__main__':` block that calls `run_migration()` so it can be run standalone: `python -m app.backend.migrate_articles`

Follow existing codebase patterns:
- Import from `.models` using relative imports
- Use `get_session()` for session management
- try/except/finally with session.close()
- Print-based logging with `[MIGRAZIONE]` prefix
- Italian comments
