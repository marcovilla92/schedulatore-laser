Add per-article phase progress visualization to dashboard.html. The dashboard already receives `article_records` (with `required_phases` and `has_started_steps`) from `GET /api/orders` and full per-article details from `GET /api/orders/{id}` in the modal.

**Changes to dashboard.html (per CONTEXT.md locked decisions):**

1. **Calendar order cards**: In the `createDayElement` function where order cards are rendered, add a small progress indicator below the client name:
   - A compact text like "3/5" showing completed articles vs total
   - Orders with all articles completed: add CSS class for "COMPLETATO" badge styling and push to end

2. **Order modal enhancement**: In the `openOrderModal` function, add a segmented horizontal progress bar above the articles table:
   - One segment per phase (LASER, PIEGA, SALDATURA, PULIZIA, SPEDIZIONE)
   - Each segment colored by status:
     - `var(--text-muted)` / grey: in attesa (article has this phase but not started)
     - `var(--accent-cyan)`: in lavorazione (phase started, not completed)
     - `var(--accent-green)`: completato (phase completed)
   - The bar represents aggregate status across ALL articles:
     - For each phase, count how many articles have it as required, how many completed, how many in progress
     - Show as a mini stacked bar or percentage fill per phase segment
   - Below the bar: "X/Y articoli completati" counter where X = articles that completed ALL their assigned phases, Y = total articles

3. **Implementation approach for the progress bar:**
   The modal already has `order.articles` with `required_phases`, `completed_phases`, `next_phase` per article. Use this data:
   ```javascript
   // Count articles completed (all required phases done)
   const totalArticles = order.articles.length;
   const completedArticles = order.articles.filter(a => a.next_phase === 'Completato' || a.is_completed).length;

   // Per-phase aggregation
   const phases = ['LASER', 'PIEGA', 'SALDATURA', 'PULIZIA', 'SPEDIZIONE'];
   const phaseStats = phases.map(phase => {
       const required = order.articles.filter(a => (a.required_phases || []).includes(phase)).length;
       const completed = order.articles.filter(a => (a.completed_phases || []).includes(phase)).length;
       // started = articles where phase is next_phase (meaning prior phases done, this one not yet)
       // For simplicity: in_progress = required - completed (approximation)
       return { phase, required, completed };
   }).filter(ps => ps.required > 0);
   ```

4. **Add CSS** for the progress bar inside existing `<style>` block:
   - `.phase-progress-bar` — horizontal flex container, height ~20px, border-radius, background rgba
   - `.phase-segment` — flex item with label, proportional width based on article count
   - `.phase-segment-fill` — inner fill colored by completion ratio (gradient from grey to green)
   - `.completion-counter` — text below bar: "X/Y articoli completati"

5. **Calendar card badges**: For orders where all articles are completed:
   - Add a small green dot or "COMPLETATO" mini badge on the calendar card
   - Use the existing `order.status` field OR compute from `article_records` if available:
     ```javascript
     const isComplete = (order.article_records || []).length > 0 &&
         (order.article_records || []).every(ar => ar.has_started_steps);  // Approximation
     ```
   - Better: check `order.status` for completion states (SPEDITO or PULIZIA_COMPLETATA etc.)
   - The calendar cards already have CSS class based on `order.status.toLowerCase()` — just ensure completed statuses get visually distinct styling

6. **Auto-refresh**: Keep existing 10-second interval. Progress bar updates automatically.

7. **Backward compatibility**: The `article_records` field may not exist for pre-v1.1 orders. Check with `if (order.article_records && order.article_records.length > 0)` before rendering progress; for legacy orders, show the old view.
